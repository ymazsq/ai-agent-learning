# Day 2 面试题：流式输出与多轮对话

对应代码：[src/day02/chat.ts](../src/day02/chat.ts)

**1. 什么是流式输出（streaming）？它解决了什么问题？**
参考答案：流式输出是模型边生成边返回 token（通常以 SSE 分块推送），而不是等全部生成完再返回。好处是首字延迟低，用户体验好，也能提前处理中间结果。代价是需要按分块拼接，并处理中途断开等异常。

**2. 多轮对话的"记忆"是怎么实现的？模型记住了什么？**
参考答案：模型不保存会话状态。每次请求都把之前的 user 和 assistant 消息放进 messages 数组重新发送，模型只是基于这次请求里的内容作答。所以"记忆"本质是客户端维护历史并每次带上。

**3. 流式输出时，如何拿到完整回复并存入历史？**
参考答案：逐个读取 chunk 中的 `delta.content` 并拼接到一个字符串变量里，流结束后，把完整字符串作为 assistant 消息追加到 history。如果中途出错，要决定是否保留这次 user 消息，本项目的做法是出错时移除它，避免历史里出现没有回复的孤立提问。

**4. 命令行交互中，`readline` 在什么情况下会丢输入？怎么处理？**
参考答案：当输入在程序还没等待 `question()` 时到达（例如管道一次性灌入），或在模型流式输出期间输入，部分行可能被丢弃。处理方式包括：在等待回复时禁用输入、排队处理用户输入，或改用事件驱动的 UI。Day 2 的测试用 `sleep` 分隔输入来规避这个问题。
