# Day 16 面试题：SSE 流式接口

对应代码：[src/day16/sse.ts](../src/day16/sse.ts)

**1. SSE 与 WebSocket 有什么区别？大模型的流式输出为什么常用 SSE？**
参考答案：SSE 是基于普通 HTTP 的单向推送，服务端持续向客户端发送消息，客户端如需发送数据要另起请求。WebSocket 是全双工协议，需要通过 Upgrade 握手切换协议，双向都能随时发送。大模型输出是服务端单向持续生成的过程，用户的提问只需一次请求，因此 SSE 足够，实现更简单，兼容代理和负载均衡，浏览器原生支持 `EventSource` 且断线自动重连。若需要中途打断、语音双向交互等场景，再考虑 WebSocket。

**2. SSE 消息的格式是什么？为什么每条消息要以空行结束？**
参考答案：每条消息由若干行组成，常见字段有 `event:`（事件名）、`data:`（数据，可多行）、`id:`（用于断线重连时的续传位置）。一条消息以空行（`\n\n`）结束，客户端只有读到空行才会分发事件。如果缺少空行，消息不会触发，多条消息也可能被合并成一条，边界丢失。

**3. 为什么 SSE 要用 `res.write` 逐块写入，而不是等全部生成后再一次性返回？**
参考答案：逐块写入可以让客户端边生成边显示，首字延迟只取决于第一个 token 的生成时间，而不是整个回答的生成时间。这种响应没有预先知道的 `Content-Length`，使用分块传输编码（chunked），连接保持打开直到 `res.end()`。普通 JSON 接口（如 Day 15 的 `/echo`）则是一次性发送完整响应，并设置 `Content-Length`。

**4. 客户端断开连接后，服务端应该怎么处理？如果是真实的大模型调用，还要注意什么？**
参考答案：服务端应监听响应对象的 `close` 事件，设置标志位并停止循环，避免继续生成 token 造成配额和费用浪费，也避免向已关闭的连接写入。若调用的是真实大模型，还需要把断开信号传给上游请求，例如用 `AbortController` 取消 `fetch`，否则上游连接会继续占用直到生成完成。应监听 `res` 而不是 `req`，因为是响应的可写状态发生变化。

**5. `curl -N` 的作用是什么？URL 中传输中文参数时为什么要做百分号编码？**
参考答案：`-N` 关闭 curl 的输出缓冲，使每条 SSE 消息到达后立即打印，便于观察流式效果。URL 规范只允许 ASCII 字符，直接发送中文时，curl 会发送 UTF-8 原始字节，服务端 Node 会把它们按 latin1 解读，导致乱码。使用 `encodeURIComponent` 或 `curl -G --data-urlencode` 编码后，服务端能正确解码。浏览器的 `fetch` 和 `EventSource` 会自动编码，POST 的 JSON body 则不需要编码。
