# Day 3 面试题：上下文管理

对应代码：[src/day03/context.ts](../src/day03/context.ts)

**1. 长对话中，为什么每轮的输入 token 会越来越多？怎么控制？**
参考答案：LLM 本身无状态，每次请求都要带上完整历史，所以输入 token 随轮数线性增长，费用和延迟也随之上升。常见控制方法有：滑动窗口截断、摘要压缩、只检索相关历史（RAG）。

**2. 截断和摘要各有什么优缺点？**
参考答案：截断实现简单、成本低，但会直接丢掉早期信息。摘要能保留要点，但会丢细节，还需要额外一次模型调用，摘要质量也会影响后续回答。实际项目通常两者结合：近期原文 + 早期摘要。

**3. 摘要失败时应该怎么处理？**
参考答案：不应丢弃原始历史。本项目的做法是摘要失败只记录错误，保留原始消息，下次再尝试压缩。这样可以避免在摘要失败时丢失信息。

**4. 如何判断一个 Agent 的上下文管理是否有效？**
参考答案：可以看三类指标：输入 token 是否趋于稳定，关键信息（如用户名字、约定）是否仍能被正确使用，以及单次调用的费用和延迟是否可接受。最好用固定的多轮测试用例做回归验证。
