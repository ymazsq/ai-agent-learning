# Day 6 面试题：最小 Agent（工具循环 + 多轮上下文）

对应代码：[src/day06/agent.ts](../src/day06/agent.ts)

**1. 手写一个 Agent 时，核心循环怎么写？如何结束？**
参考答案：每一步把当前 messages 和工具定义发给模型。如果返回 `tool_calls`，就执行工具，把结果以 `tool` 消息追加，然后进入下一步；如果没有 `tool_calls`，就取 `content` 作为最终回答并结束。同时要设置最大步数，防止无限循环。

**2. 为什么按"轮"（用户消息边界）压缩历史，而不是按消息条数截断？**
参考答案：一轮里可能有 `user → assistant(tool_calls) → tool → assistant` 这样的连续消息。按条数切会把 `assistant(tool_calls)` 和它对应的 `tool` 结果拆开，留下孤立的 `tool` 消息或缺少结果的 `tool_calls`，接口会报错。按用户轮切分可以保证每组工具调用都完整保留或完整压缩。

**3. 一轮执行中途失败（比如第二次模型请求抛错），历史该怎么处理？**
参考答案：应该整轮回滚，把历史截断回这一轮开始前的长度。否则历史里会留下已经执行过的 `tool_calls`，但没有最终回答，下一轮对话时模型看到的上下文是残缺的，行为不可预测。回滚的代价是这一轮的工具副作用（如已写入的文件）不会被撤销，这一点需要在产品层面说明。

**4. 工具返回错误时，应该抛异常还是作为结果回传？为什么？**
参考答案：应该作为 `tool` 消息回传，例如 `{ error: "路径不在 workspace/ 目录内" }`。这样模型能看到错误原因并调整策略，比如换一个路径或换一种方法。如果直接抛异常，整轮都会失败，Agent 失去自我修正的机会。但要注意，回传的错误也不能包含敏感信息。

**5. 如何限制文件工具只能访问某个目录？这种限制有什么局限？**
参考答案：把用户给的路径和基准目录（如 `workspace/`）做 `path.resolve`，检查结果是否仍在基准目录之下，并拒绝 `..` 和绝对路径。局限是：只对文件工具生效。如果同时提供了 `run_command` 这类通用命令工具，模型可以用 `cat ../xxx` 绕过文件工具的限制。真正的隔离需要在命令层面做白名单、沙箱或用户确认（本项目 Day 7 处理）。

**6. 为什么不能依赖 system prompt 告诉模型"不要访问外部文件"来保证安全？**
参考答案：prompt 约束只是建议，模型可能误解、忽略或被输入中的指令诱导。Day 6 的实际运行中，模型就错误地说"无法用 `run_command` 绕过限制"。安全边界必须由代码强制执行，比如路径校验、白名单、沙箱和人工确认。

**7. 工具调用的 `arguments` 为什么要做解析和校验？**
参考答案：`arguments` 是模型生成的 JSON 字符串，可能格式错误或字段缺失。应用必须先 `JSON.parse` 并校验字段类型，失败时把错误回传给模型。不能假设参数总是合法的。
