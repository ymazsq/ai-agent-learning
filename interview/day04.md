# Day 4 面试题：结构化输出

对应代码：[src/day04/extract.ts](../src/day04/extract.ts)

**1. 为什么不能直接 `JSON.parse` 模型输出就使用？**
参考答案：`response_format: json_object` 只能保证输出是合法 JSON，不能保证字段名、类型、取值范围正确，也不能保证缺字段。模型输出是不可信的外部输入，必须像处理用户输入一样做 schema 校验，再交给后续逻辑使用。

**2. schema 校验失败时，应该重试还是直接报错？**
参考答案：通常先重试，把原输出和具体错误（如"priority 必须是 low、medium 或 high"）放回对话，让模型修正，这对格式小错误很有效。重试有上限，超过后报错或走兜底逻辑，避免无限循环和费用失控。对于不可恢复的错误（如权限不足）则应直接报错。

**3. 结构化输出和 Function Calling 有什么区别？**
参考答案：结构化输出是让模型的最终回复符合某个格式，由应用解析后使用。Function Calling 是模型主动选择要调用的工具并生成参数，由应用执行工具后把结果返回给模型，模型再继续推理。前者解决"输出长什么样"，后者解决"要不要、怎么调用外部能力"。

**4. 为什么抽取日期类信息时，要把当前日期放进 prompt？**
参考答案：模型没有实时时间，无法把"明天""下周五"换算成具体日期，只能输出 null 或猜测。把当前日期作为上下文传入，才能可靠地完成相对日期的换算。这也是 Agent 需要注入环境信息（时间、用户身份、可用工具）的原因。
