# Day 8 面试题：System prompt 分层

对应代码：[src/day08/agent.ts](../src/day08/agent.ts)

**1. 为什么要把 system prompt 拆成多层，而不是写成一整段长字符串？**
参考答案：不同部分的变化频率和来源不同。身份和语言基本固定；工具规则随工具集合变化；运行时信息（时间、文件、摘要）每次请求都不同。拆层后每一部分有单独的来源和修改位置，可以单独测试，也能在日志里看清模型实际收到了什么。

**2. 运行时层为什么要每次请求重新生成？**
参考答案：文件列表、摘要、时间都会随对话变化。如果只在启动时生成一次，模型会基于过时的信息做判断，比如文件已经存在却又重复创建。Day 8 的桩测试就验证了：写入新文件后，下一次请求的运行时层已经包含它。

**3. 能不能只靠 prompt 里的规则来限制工具行为？**
参考答案：不能。prompt 规则只是对模型的提醒，模型可能误解、忽略，或被输入中的内容诱导。真正的边界必须在代码中强制执行，例如路径校验、命令白名单、用户确认。prompt 规则的作用是减少无效请求和让模型解释清楚拒绝原因，而不是替代校验。

**4. 规则层为什么要从常量生成，而不是手写？**
参考答案：手写的规则很容易和代码脱节。比如代码白名单里增加了一个命令，但 prompt 没有更新，模型就不知道它可用；或者 prompt 说允许，代码却拒绝。从同一个常量生成，可以保证两者一致，修改时只需要改一处。

**5. 三层拼接时，顺序有什么讲究？**
参考答案：通常把稳定、优先级高的内容放在前面（身份、核心规则），把变化快的内容放在后面（运行时状态）。这样前缀更稳定，便于利用服务端的 prompt 缓存；而且规则在前，模型会优先遵守。具体顺序要结合模型和接口的缓存策略来确定。
