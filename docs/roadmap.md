# 转型路线图：前端 → Agent 开发

更新：2026-11-05
起点：2026-11-02（Day 1）　目标：2027-02 中下旬开始面试

## 1. 目标与边界

两条方向并行，共用同一条主线项目：

| 方向 | 要求 | 本计划的覆盖方式 |
|---|---|---|
| A. AI 全栈开发工程师 | 补齐后端：Node 服务、HTTP/SSE、数据库、鉴权基础 | P2 后端、P3 前端流式 UI、P6 部署 |
| B. Agent 应用开发工程师 | 面向具体业务场景的 Agent：工具设计、检索、评测、权限 | P1 工具与安全、P2 RAG、P5 评测 |

边界：
- 业务场景只用个人学习数据或虚构数据。**不使用、不复制公司的代码、文档或数据**。
- 不做模型训练。Python 只做 W15–W16 的阅读和小改动，不做系统开发。
- 包管理用 pnpm；语言用 TypeScript。

时间预算：工作日 3–4 小时，周末不安排学习。按模块推进，不绑定周数。

## 2. 毕业作品

**个人知识助手（Agent + 全栈）**：一个 Web 应用，用户上传自己的笔记，Agent 能检索回答，能调用工具（读文件、创建任务、查日期），流式输出，工具调用过程可见，写操作需要用户确认。

必须具备：
- 后端：Node 服务，SSE 流式接口，SQLite 或 Postgres 持久化会话
- 前端：流式渲染、工具调用卡片、确认对话框
- Agent：手写循环，上下文管理，RAG 检索，权限与危险命令拦截
- 评测：一组固定问题集，能比较两版 prompt 或检索策略的效果
- 工程：Docker 部署，README 含架构图、运行方式、取舍说明、评测结果

## 3. 学习模块

参考市场上 AI Agent 开发工程师培训的常见结构（如 [华测教育的 AI Agent 开发课程](https://www.huace-ai.com/course/ai-agent/)：模型应用基础 → 提示词与可靠输出 → 知识库与 RAG → Agent 与工具调用 → 工作流 → Skill/MCP → 评估与安全 → 部署交付），按能力模块组织。每个模块结束时都有一个可提交、可演示的阶段实践。

不再把每个 Day 绑定到固定周和日期。已完成的 Day 编号保持不变，后续按模块顺序编号。

每个模块结束时对照"出口标准"自检。不合格的部分在下一个模块前补齐，不跳过。

| 模块 | 内容 | 对应 Day | 阶段实践与出口标准 |
|---|---|---|---|
| 一、模型应用与 Agent 核心 | API、流式、结构化输出、Function Calling、手写 Agent 循环、工具安全、system prompt、会话持久化、上下文压缩 | Day 1–10（已完成） | 手写 Agent 能循环调用工具、拦截危险命令、跨会话恢复、压缩长上下文；能解释每一步回传的消息格式。遗留：复现"长对话爆上下文" |
| 二、企业知识库与 RAG | 文本切分与向量检索（已完成）；带引用的问答与拒答；混合检索（关键词 + 向量）与 Rerank；RAG 质量评估 | Day 11（已完成）、Day 12–14 | 交付带引用、无依据时拒答的问答；能给出 5 个问题的命中结果并说明失败原因 |

## 5. 风险与应对

- **时间不够**：优先保留 RAG、后端、评测、部署。MCP 与 LangGraph 可以缩减为演示，不删除。
- **某一周卡住**：先写下问题，用一天时间找资料和开源实现对比，仍然卡住就记录在学习记录里，继续往下，不无限停留。
- **内容偏离**：每两周对照 2–3 个真实岗位的要求检查一次，必要时调整。
- **太多主题，难以形成闭环**：每个主题都要落到主线项目的一次提交上，没有提交的不算完成。
